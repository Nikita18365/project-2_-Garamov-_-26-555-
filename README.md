# Primitive DB

Консольное приложение на Python, имитирующее работу простой базы данных.

Проект позволяет создавать и удалять таблицы, хранить их структуру и данные в JSON-файлах, а также выполнять основные CRUD-операции: добавление, чтение, обновление и удаление записей.

В проекте используются Poetry, Ruff, PrettyTable, декораторы, замыкания и файловое хранение данных.


## Возможности

- создание и удаление таблиц;
- просмотр списка таблиц;
- автоматическое создание столбца ID:int;
- хранение метаданных таблиц в JSON;
- хранение данных каждой таблицы в отдельном JSON-файле;
- добавление записей;
- выборка всех записей или выборка по условию;
- обновление записей;
- удаление записей;
- просмотр информации о таблице;
- проверка типов данных;
- автоматическая генерация ID;
- красивый табличный вывод через PrettyTable;
- централизованная обработка ошибок с помощью декораторов;
- подтверждение опасных операций;
- измерение времени выполнения операций;
- кэширование результатов select с помощью замыкания;

## Поддерживаемые команды

| Команда | Описание |
| --- | --- |
| `create_table <имя> <столбец1:тип> ...` | Создать новую таблицу с указанными столбцами. Столбец `ID:int` добавляется автоматически |
| `list_tables` | Показать список всех существующих таблиц |
| `drop_table <имя_таблицы>` | Удалить указанную таблицу с подтверждением действия |
| `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` | Добавить новую запись в таблицу. Значение `ID` генерируется автоматически |
| `select from <имя_таблицы>` | Показать все записи таблицы |
| `select from <имя_таблицы> where <столбец> = <значение>` | Показать записи, соответствующие условию |
| `update <имя_таблицы> set <столбец> = <новое_значение> where <столбец> = <значение>` | Обновить записи, соответствующие условию |
| `delete from <имя_таблицы> where <столбец> = <значение>` | Удалить записи, соответствующие условию, с подтверждением действия |
| `info <имя_таблицы>` | Показать структуру таблицы и количество записей |
| `help` | Показать справочную информацию |
| `exit` | Выйти из программы |

## Типы данных

В системе поддерживаются следующие типы данных:

* `int` - целые числа
* `str` - строки
* `bool` - логический тип (`true` / `false`)

> **Примечание:** Столбец `ID:int` добавляется в каждую таблицу автоматически, если вы не указали его самостоятельно при создании.


## Создание таблицы

Синтаксис:

```text
create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...
```

Пример:

```text
create_table users name:str age:int is_active:bool
```

Результат:

```text
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
```

Столбец `ID:int` создаётся автоматически, если пользователь не указал его самостоятельно.

## Просмотр списка таблиц

```text
list_tables
```

Пример:

```text
- users
```

## Удаление таблицы

```text
drop_table users
```

Перед удалением программа запрашивает подтверждение:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
```

При вводе `y` таблица удаляется. При любом другом ответе операция отменяется.

## CRUD-операции

Данные каждой таблицы хранятся в отдельном JSON-файле в директории `data/`.

Например, записи таблицы `users` хранятся в:

```text
data/users.json
```

### Добавление записи - INSERT

Синтаксис:

```text
insert into <имя_таблицы> values (<значение1>, <значение2>, ...)
```

Пример:

```text
insert into users values ("Sergei", 28, true)
```

Результат:

```text
Запись с ID=1 успешно добавлена в таблицу "users"
```

Поле ID указывать не нужно - оно генерируется автоматически.

Если в таблице определены:

```text
ID:int, name:str, age:int, is_active:bool
```

пользователь передаёт только:

```text
name, age, is_active
```

То есть:

```text
insert into users values ("Anna", 31, false)
```

### Чтение всех записей - SELECT

```text
select from users
```

Пример результата:

```text
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
| 2  |  Anna  |  31 |   False   |
+----+--------+-----+-----------+
```

### Чтение по условию - SELECT WHERE

```text
select from users where age = 28
```

Результат:

```text
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+
```

Строковые значения необходимо указывать в кавычках:

```text
select from users where name = "Sergei"
```

Для чисел кавычки не используются:

```text
select from users where age = 28
```

Для логических значений используются:

```text
true
false
```

### Обновление записи - UPDATE

Синтаксис:

```text
update <имя_таблицы> set <столбец> = <новое_значение> where <столбец> = <значение>
```

Пример:

```text
update users set age = 29 where name = "Sergei"
```

Результат:

```text
Запись с ID=1 в таблице "users" успешно обновлена.
```

После обновления:

```text
select from users
```

может вернуть:

```text
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  29 |    True   |
| 2  |  Anna  |  31 |   False   |
+----+--------+-----+-----------+
```

### Удаление записи - DELETE

Синтаксис:

```text
delete from <имя_таблицы> where <столбец> = <значение>
```

Пример:

```text
delete from users where ID = 1
```

Перед удалением программа запрашивает подтверждение:

```text
Вы уверены, что хотите выполнить "удаление записи"? [y/n]:
```

При вводе:

```text
y
```

запись удаляется.

При любом другом ответе:

```text
Операция отменена.
```

### Информация о таблице - INFO

```text
info users
```

Пример:

```text
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 2
```

## Валидация данных

При добавлении и изменении данных программа проверяет соответствие значений типам столбцов.

Например, если столбец:

```text
age:int
```

то корректное значение:

```text
28
```

а значение:

```text
"28"
```

является строкой и не соответствует типу `int`.

Также программа проверяет:

- существование таблицы;
- существование столбца;
- количество переданных значений;
- корректность типов;
- корректность синтаксиса команд;

## Хранение данных

Метаданные таблиц хранятся в файле:

```text
db_meta.json
```

Например:

```json
{
    "users": {
        "columns": [
            {
                "name": "ID",
                "type": "int"
            },
            {
                "name": "name",
                "type": "str"
            },
            {
                "name": "age",
                "type": "int"
            },
            {
                "name": "is_active",
                "type": "bool"
            }
        ]
    }
}
```

Записи каждой таблицы хранятся отдельно.

Пример `data/users.json`:

```json
[
    {
        "ID": 1,
        "name": "Sergei",
        "age": 28,
        "is_active": true
    }
]
```

Это обеспечивает сохранение структуры и данных между запусками программы.


## Декораторы и замыкания

В проекте используются декораторы и замыкания для повышения надёжности и уменьшения дублирования кода.

### Обработка ошибок

Декоратор:

```text
handle_db_errors
```

централизованно обрабатывает ошибки операций базы данных, включая:

- FileNotFoundError;
- KeyError;
- ValueError;
- другие непредвиденные исключения;

Это позволяет не дублировать одинаковые блоки try...except в каждой функции.

### Подтверждение опасных операций

Декоратор:

```text
confirm_action
```

используется для операций удаления.

Пример:

```text
Вы уверены, что хотите выполнить "удаление записи"? [y/n]:
```

или:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
```

При вводе y операция выполняется.

При любом другом ответе:

```text
Операция отменена.
```


### Измерение времени выполнения

Для операций insert и select используется декоратор:

```text
log_time
```

Для измерения времени применяется time.monotonic().

Пример вывода:

```text
Функция insert выполнилась за 0.000 секунд
```

или:

```text
Функция select выполнилась за 0.000 секунд
```


### Кэширование

Для повторяющихся запросов select реализовано кэширование с помощью замыкания:

```text
create_cacher()
```

Кэш хранится во внутреннем словаре замыкания.

При повторном запросе сначала выполняется поиск результата в кэше. Если соответствующего результата нет, он вычисляется и сохраняется для последующих вызовов.

## Структура проекта

Основные модули приложения:

```text
src/
├── __init__.py
└── primitive_db/
    ├── __init__.py
    ├── constants.py
    ├── core.py
    ├── decorators.py
    ├── engine.py
    ├── main.py
    ├── parser.py
    └── utils.py
```

Назначение модулей:

- main.py - точка входа в приложение;
- engine.py - основной цикл программы, обработка пользовательского ввода и маршрутизация команд;
- core.py - бизнес-логика таблиц и CRUD-операций;
- utils.py - загрузка, сохранение и удаление JSON-файлов;
- parser.py - разбор сложных команд insert, select, update, delete, info;
- decorators.py - обработка ошибок, подтверждение операций, измерение времени и кэширование;
- constants.py - именованные константы проекта;
